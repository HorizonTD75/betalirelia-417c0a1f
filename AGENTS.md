
- Financial-aid cocoon pages render only from the Markdown articles in src/content/aides-financieres/ via one shared page; frontmatter is SEO spec, never visible text. Why: single editorial source, no duplicated content.
- DMLA cocoon child pages (src/pages/maladies/dmla/) are static JSX generated from the validated Markdown, using DmlaChildLayout; no content arrays/.map. Why: the external static-HTML converter loses mapped lists/FAQ.
- Optional trackers (GA4, Clarity, Meta Pixel, HubSpot, Albacross) load only via the LIRELIA CONSENT LOADER in index.html, triggered by stored consent; consent events go to https://lirelia.fr/api/consent.php via src/lib/consentLog.ts. Why: no tracker before consent, works in static HTML export.
- Choice-loupe guides use delimited public Markdown and a dedicated shared layout, with real anchors and existing head/prerender metadata; pending photography requests remain preview-only. Why: preserve validated editorial content and static navigation without modifying tracker logic.
- Route metadata is owned by routeMeta and guide frontmatter; the same head helpers serve React navigation and per-route static HTML. Why: avoid stale navigation tags and duplicated SEO sources.
- Guide FAQ answers are extracted verbatim from Markdown into native details/summary and remain in the DOM even when closed. Why: accessible keyboard interaction and static export compatibility.
- Choice-loupe photo zones render from IMAGE_ZONE comments; briefs show only while CHOICE_PHOTO_BRIEFS_ENABLED (src/content/choix-loupes/editorialMode.ts) is true, and final photos are attached by zone id in FINAL_PHOTOS. Why: prepare shoots in Preview without touching article text; switch off before public launch.
